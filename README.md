# kb-tools — детерминированные инструменты базы знаний

Слой готовых программ между ИИ-агентами и мастер-папкой KnowledgeBase
(«Этап 5б» плана). Агент не пишет одноразовые скрипты — вызывает эти команды.
Принцип: inspection разрешается широко, mutation — узко; kb-lint по построению
read-only, и этот инвариант менять нельзя.

## Состав (v0.1 — по «правилу трёх повторений» пакет растёт из friction-лога)

- `bin/kb-new` — создать заметку из `templates/` с корректной YAML-шапкой,
  транслит-именем по конвенции и заполненными полями (mutation: только новые файлы).
  Типы: note, decision, episode, skill, person, review (разбор из канала
  Telegram → `inbox/telegram/`, имя без даты, чтобы переезд в `reference/`
  не ломал ссылки).
- `bin/kb-lint` — валидатор базы или файла: обязательные поля шапки, форматы дат,
  статусы, битые wiki-ссылки (включая вложения `![[файл.base]]`, картинки, PDF),
  сироты, конвенции имён, просроченное (inspection). `inbox/` освобождён от
  проверок, кроме `inbox/telegram/`: туда пишет автоматика, поэтому шапки и
  ссылки проверяются, а сиротство — нет (зона «на изучении»).
- `lib/kbcore.py` — единственное место, где закодировано «понимание» формата
  заметки (парсер шапок и ссылок, области проверки).
- `tests/run_tests.py` — фикстуры заведомо битых заметок; запуск: `python3 tests/run_tests.py`.

Коды: E1 нет/битая шапка · E2 нет обязательного поля · E3 формат даты ·
E4 недопустимый status · E5 tags не список · E6 битая [[ссылка]] ·
E7 имя в journal/ не YYYY-MM-DD-tema.md · E8 basis вне словаря · W1 сирота · W2 имя не латиницей ·
W3 просрочено valid_until · W4 нет исходящих ссылок · W5 basis: model в reference/.

## Контракт команд

`--json` (машиночитаемо) · exit-код 0/1 · `--dry-run` у мутирующего ·
`--help` (полная справка) · корень базы: `--root` > `$KB_ROOT` > поиск вверх
от текущей папки до AGENTS.md.

## Установка (Mac)

```bash
git clone https://github.com/DIZabolotny/kb-tools ~/dev/kb-tools
cd ~/dev/kb-tools && ./install.sh ~/путь/к/базе
```

install.sh делает: `chmod +x`, симлинки в `~/.local/bin/`, подсказку про
`KB_ROOT` в профиле шелла. Требуется только python3 (stdlib, без зависимостей).

## Настройки базы: `.kb.toml`

Необязательный файл в корне базы (рядом с AGENTS.md):

```toml
author = "Имя"              # автор по умолчанию для kb-new (иначе $KB_AUTHOR, иначе "owner")
timezone = "Europe/Kyiv"    # часовой пояс для created и имён эпизодов (иначе системный)
```

`timezone` важен для автоматики: GitHub Actions работает в UTC, без него
заметки получат время на несколько часов раньше местного.

## Дата и время

`kb-new` пишет `created: YYYY-MM-DDTHH:MM` (формат «Дата и время» Obsidian),
эпизоды называет `journal/YYYY-MM-DD-HHMM-tema.md` — несколько записей за день
идут по порядку. В шаблонах доступны `{{date}}` и `{{time}}`. `kb-lint`
принимает и старый формат `YYYY-MM-DD`.

## В GitHub Actions

Репозиторий публичный, поэтому сценарий в приватной базе подключает его без токена:

```yaml
- uses: actions/checkout@v4                 # база
- uses: actions/checkout@v4
  with: { repository: DIZabolotny/kb-tools, path: .kb-tools }
- run: python3 .kb-tools/tests/run_tests.py && python3 .kb-tools/bin/kb-lint --root .
```

## Правила для агентов (дублируются в AGENTS.md базы)

1. Новые .md создавать через `kb-new`, не вручную.
2. После правки любого .md — `kb-lint --file <путь>`; ошибки чинить сразу.
3. Мутирующие операции — только с одобрения владельца.
4. Нет нужной команды и операция повторяется — строка `[tooling] ...` во friction-лог.

## Инварианты сопровождения

- kb-lint никогда не пишет в базу; «чинилки» — только отдельными mutation-командами.
- Изменение схемы шапки = правка kbcore + тестов + AGENTS.md одной сессией.
- AGENTS.md формулирует намерение для человека; kb-lint — единственный арбитр для машины.
